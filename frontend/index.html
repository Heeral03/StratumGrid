Core System Design

Algorithmic Complexity & Architecture

How FleetScale solves physical warehouse concurrency without expensive linear traversals.

Traditional $O(N)$ Approach

Linear Subtree Traversal

Standard warehouse execution systems iterate over all sub-nodes in a zone or aisle ($O(N)$ time) before granting spatial access.

  • High contention delays during multi-robot dispatch
  • Risk of race conditions under concurrent requests
  • High CPU overhead on large warehouse trees
FleetScale $O(h)$ Approach

Hierarchical Counter Propagation

Every tree node stores parent pointers and an atomic locked_descendant_count counter. Lock validation checks ancestor state and descendant counters in $O(h)$ time where $h$ is tree height.

  • Constant validation time bound by tree depth
  • Atomic state mutation protected by thread locks
  • Automatic child lock consolidation via lock upgrade
API Specification

REST API Endpoints

POST /api/v1/resource/lock

Hierarchical Lock Acquisition

Validates ancestor freedom and zero descendant locks before acquiring an exclusive spatial lock on target node.

POST /api/v1/resource/unlock

Controlled Lock Release

Unlocks target node and decrements descendant counters upward along the parent chain.

POST /api/v1/resource/upgrade

Dynamic Zone Upgrade

Consolidates multiple child locks owned by the same agent into a single parent zone lock.
